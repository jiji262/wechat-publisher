# 改稿清单(阶段 3.5 专用)

**只在阶段 3.5 读。** 阶段三写稿时不读本文件:禁令参与生成,会被换个说法写回稿子里。

读之前先记住三点:

1. 本文件只描述**动作**,不给可以照抄的句子,也不给"允许用几次"的配额。lint 只列需要处理的命中,分两种:落在零容忍位置的逐条列出(`position`);其余规则在全文密度过高时把整条规则列出(`density`)。输出不显示检测上限,改稿也不以"没超"为目标,不要去凑。清单是下限,不是全部:自己读到的同类动作照样改。
2. 按动作判定。换句式、倒装、省掉连接词、套上高亮或引号,做的还是同一个动作,照样算命中。
3. 改稿是为了让读者读着像这个账号的作者本人写的,不是为了压低检测分数。分数低不等于像人。

规则 id 与 `ai_score.py --advisory` 输出、`humanize_log.md` 的"规则"列一一对应。

## A 层:Claude 中文腔(advisory)

标题、摘要、小标题、图注(贴图模式加上要点)是零容忍位置,否定对照套在行内高亮里也按零容忍处理;没有密度余量的规则(编造的反应、否定排队之类)出现一次就列。这些命中标为 `position`,逐条处理:能改就改,确需保留就逐条写保留行。其余命中标为 `density`,按规则整体处理。

| 规则 id | 动作 | 为什么像 AI | 改法原则 |
|---|---|---|---|
| `neg_contrast` | 先否定一个说法,再亮出自己的说法:「不是 X,(而)是 Y」「这不是 A,这是 B」「Y,不是 X」「你以为……其实……」「不只是……更是……」「与其说……不如说……」「看似……实则……」「以为……,实际……的,是……」「A 不代表 B,C 不代表 D」;正文里「A 和 B 是两回事」按密度计 | X 多半是作者替读者虚构的误解,只为给 Y 制造落差。Claude 中文里这类翻案句的频率远高于人类写作者 | 遮住否定那半句再读,意思不变就删。X 真是有人持有的误解,就写清是谁、出处在哪,再写 Y 和证据 |
| `neg_listing` | 连排几个否定,最后落到一个肯定(「不是 A,不是 B,就是 C」) | 排比加翻案,两层修辞叠在一起,没有信息 | 直接把 C 写成一句事实 |
| `empty_short_para` | 没有信息的短句单独成段:只表态、只制造悬念、只有一个数字或一串数字(单独成段的章节序号 1 / 01 / 一 / (一) / Part N 不算) | 靠分段制造停顿和戏剧感;旧规则为了"句长抖动"插进来的碎句就是这种 | 并回上下文。数字放进有主语、有单位的完整陈述句 |
| `fake_reaction` | 写作者自己的身体或情绪反应(惊讶、发笑、怀疑、反复读同一处之类),brief.experiences 里没有 | 写稿的是模型,没有反应可言。编出来的反应是最容易被识破的假人味,也是以真人名义发布不实内容 | 删掉,让事实本身出场 |
| `candor_tic` | 给判断贴"坦诚""口语"标签的插入语,以及账号禁用词(词表在 `zh_rules.TIC_PATTERNS`、`zh_rules.CANDOR` 与账号禁用词表;研究动作族单篇不检查,只由 fingerprint 按跨篇文档频率监控,同一篇里反复用要自己看) | 旧 voice 把这类词当插入指令,结果在固定位置跨篇复现,成了能被认出来的印章 | 删掉标签,判断照写 |
| `perf_imperfect` | 表演出来的跑题、反悔、自嘲,或"写到这里"式的写作过程旁白 | 旧清单把它当人味配额插入。真实写作者改口,一定伴随新的材料 | 删掉。确实改了判断,就直接写新材料和新判断 |
| `salience` | 先宣告"重要""关键""最值得""真正的 X",再说内容;自封最高级 | 宣告本身不带信息。重要性宣告是 Claude 最顽固的痕迹之一 | 删掉宣告,让内容和后果说明重要性。确需比较,写出比较对象和依据 |
| `staged` | 预告下面要讲什么,或者给段落加主持人式的过场 | 把演讲稿的串场搬进文章 | 直接进入下一条信息 |
| `colon_reveal` | 冒号前铺悬念,冒号后"揭晓"结论(常配高亮) | 制造揭晓节奏,结论被包装成戏剧 | 写成完整陈述句。引出代码、表格、原话、清单的冒号不算 |
| `self_qa` | 自己提问,紧接着自己回答 | 伪对话,问题只是答案的前缀 | 直接写原因。真的在问读者、或问题确实悬而未决的问句不算 |
| `strawman` | 先替读者设定一个错误认知,再出手纠正 | 对立面是虚构的 | 直接陈述事实。要写"原先以为",必须有出处(brief.experiences 或带链接的原话) |
| `restate` | 用复述类连接语把上一句换个说法再说一遍 | 话说两遍,不信任读者 | 事实说一遍。只补读者自己推不出来的那一点 |
| `aphorism_end` | 小节末或全文末用一句短格言、对仗句或加粗结论收束;图注带结论、总结、启示、教训、N 个坑这类标签词,或以「。」「!」结尾又带论断词(纯描述的图注带句号不算) | 格言收尾是模板化结尾,跨篇高度一致;图注写成论点句等于在图下面再收一次尾 | 删掉,看上一句是否已经是自然的停止点;通常是。图注改成描述图里画了什么的短语,去掉标签词和论断 |
| `cta_end` | 结尾套行动号召模板(只做一件事、去评论区、关注转发之类) | 同一天两篇能出现几乎相同的号召 | 删掉。确实要给读者下一步,写具体的链接、命令或日期 |
| `triad` | 三项排比、三个碎句连排、为了凑满三条而凑 | 三是模型偏好的节奏,实际数量不是三也会被凑成三 | 按实际数量写。两项并列不算问题 |
| `couplet` | 对仗和回环:前后两句结构对称、词语互换 | 格言化,读着像标语 | 拆开,写成普通陈述,信息保留 |
| `heading_template` | 小标题套模板:数量模板、序数序列、情绪钩子词、否定对照、"真正的 X" | 序数小标题在几个模型里 Claude 用得最多;数量模板把文章钉死成清单体 | 小标题写这一节讲的具体内容。编号只留给真实的操作步骤 |
| `dash_overuse` | 破折号用得多 | Claude 的破折号用量是人类的数倍 | 改成逗号、括号,或者拆成两句 |
| `highlight_sentence` | 整句高亮、加粗结论句 | 富文本层的 AI 指纹,每节一句加粗金句尤其典型 | 行内标记只给数字、命令、产品名、版本号 |
| `no_stance` | 用"各有优劣""取决于场景"一类话收口,不给取舍 | 安全中立,读完不知道作者站哪边 | 有 brief.stance 就按 stance 写取舍和理由。证据不够就写清证据缺在哪、卡在哪,不硬造结论 |
| `unsourced_experience` | 第一人称亲历,在 brief.experiences 里找不到对应 | 写稿的人没有亲历,这类句子只能是编的 | 删掉;或者请用户确认后补进 experiences |
| `unsourced_quote` | 转述某人(同事、朋友、读者、网友)的话,没有链接或出处 | 编造轶事;AI 编的引语往往和正文一个腔调 | 删掉;或者换成 research.md 里带链接的原话 |
| `hedge_stack` | 同一句里叠几层限定(可能、或许、某种程度上之类) | 层层免责,判断被稀释 | 只留最准确的一个;或者写出不确定的具体原因 |
| `false_agency` | 把数据、工具、指标写成会说话、会思考的行动者;拟人化的职业喻体 | 假行动者,读者看不出到底是谁做了什么 | 写回真实的行动者和动作 |

另有几类没有对应检测规则、改稿和冷读时顺带看的读感项:段首书面连接词堆叠(此外 / 与此同时 / 综上之类连续出现在段首);没有具体支撑的空泛褒义评价(可靠、扎实、优雅、强大之类);给自己的概念或新造词打引号,引号里不是任何人说过的话(去掉引号直接用词;是别人的原话就补上谁说的、出处);几乎每段都用一句短评收尾(划得来、站得住、挑不出毛病之类的评价挂在段尾,形状全文一样);术语解释过勤(每个名词都挂括号或「也就是」,读着像教程)。

### 计分伪影(artifacts,直接改,不能保留)

这些是确定性的问题,计入总分(罚分),改掉就行,不需要讨论:

| 规则 id | 是什么 |
|---|---|
| `functional_heading` | 功能性小标题:开篇、引言、前言、导语、写在前面/最后、结语、总结、尾声这类,或者"角色标签 + 冒号 + 正文"的小标题(只有标签没有正文的,输出里显示为 `functional_heading_bare`) |
| `instruction_echo` | 旧版写作指令里的可复制句被搬进了正文(词表在 `zh_rules.INSTRUCTION_ECHO`) |
| `reader_shout_bait` | 对读者喊话、求关注求点赞的模板 |
| `spaced_dash` | 破折号两侧加空格 |
| `halfwidth_drift` | 汉字之间大量用半角标点 |
| `zero_width` | 零宽字符和双向控制字符(粘贴残留)。`publish.py` 发布前自动清除并打印清除了几个,不用手改 |
| `soft_adversarial` | 零星的疑似粘贴残留:希腊字母夹在英文词中间、个别康熙部首。删掉或换成正常字符 |

**硬门** `adversarial_chars`(不在 artifacts 里,单独打印为「硬门:」一行):同形字——长得像拉丁字母的西里尔 / 希腊字母紧挨汉字、混在英文词里或整词由它们组成;康熙部首成批出现也算。命中直接拒发,通常是粘贴残留,删掉换成正常字符。

### 词表(phrases / vocab,计分)

GPT 时代的套话和高频词由 `ai_score.py` 逐条列出,词表真源是共享词表(`scripts/_humanizer_lexicon.json` 的 `zh-set-phrase` 等类别)。零容忍,直接引语除外。改法是重写整句,换成具体的动作或事实,不做同义替换。

## B 层:材料与亲历

1. **亲历只来自 brief.experiences。** 正文里写成"我 + 亲身经历"的句子,必须能对上 experiences 里的某一行。experiences 为"无"时,第一人称只用于三类:可核对的研究动作(写清对象和结果,读者能顺着复核),用户在 brief.stance 里确认过的判断,以及有 materials 支撑的局部取舍建议。不编时间、神态、反应。
2. **具体数据不降级,也不编。** 原文和材料里已有的具体数据,不许换成泛指的数量词;材料里没有的数字一个都不写。终稿的数字和引语要能在 research.md 或 brief.materials 里找到,`fidelity_check.py` 会逐条核对。
3. **引语要有出处。** 引用别人的话必须写明出处,保留原话的不平整;没有真实引语就不引。不写没有链接的转述。
4. **全文立场只来自 brief.stance。** 不为了显得有观点而造一个犀利判断。基于 materials 的局部评价和取舍(哪个更快、适合什么场景、哪一步容易卡住)不受 stance=无 限制,写清依据即可。材料不够时,写明证据不足、暂不下结论、卡在哪一步,这本身就是有用的信息。
5. **类比和喻体**:只用在读者确实难懂的地方,喻体贴合读者的日常经验,同一个喻体不重复用,不限定地域意象。

---

brief front matter 里写 `dialogue: true`(对话体)或 `faq: true`(问答体)时,`empty_short_para` / `self_qa` 不再检查;只在文章真是这种体裁时写,正文里的同名字样不算。

## C 层:豁免表(这些都不是改写理由)

下面这些情况,lint 没报就不要动;冷读提出来,也不能单凭这一点改:

| 情况 | 说明 |
|---|---|
| 真问句 | 真的在问读者,或者问题确实悬而未决。人类正文里的问句比 AI 多 |
| 比喻 | 普通比喻不是 AI 味(拟人化职业喻体除外,见 `false_agency`) |
| 两项并列 | 句内两项排比是正常表达 |
| 长句、流水句 | 一口气说完的长句是中文常态,不必为"句长抖动"拆碎 |
| 被动句 | 该用就用 |
| 同一专名反复出现 | 人类比 AI 更常重复同一个名词。不要为避免重复做同义轮换 |
| 短段落本身 | 短段落有信息就没问题,问题只在"无信息的短句单独成段" |
| 偶尔一次的书面词 | 单独一处"进行""作为"之类不构成问题 |
| 承上启下的衔接 | 把两段逻辑接起来的句子是文章的骨头,删光了读起来就是一条条罗列 |
| 有依据的态度 | 紧挨着事实的好恶、意外、不满,是作者在场的证据;要改的只是没有依据的空表态 |
| 类比 | 帮读者理解机制的对照(main 号尤其需要);错位或代替了真实机制的才改 |
| 按顺序讲的经过 | experiences 里的动作按发生顺序讲,是故事线,不是冗余 |

## D 层:改法与冷读

### 改法顺序

先看这句在文章里干什么,再决定怎么动:

1. **套路句**(命中 A 层的动作):它想表达的意思往往是对的,问题在包装。把意思换成具体的判断或事实重写;只有拿掉包装后什么都不剩时才删。
2. **纯复述**(同一件事换个说法再讲一遍):删。
3. **衔接、态度、类比、经过**(见 C 层):不是 AI 味,照留;要改也只是改得更具体。
4. **改完通读一遍**:如果比初稿更像说明书(只剩事实,看不出作者觉得哪里重要),往回补:按 SKILL.md 阶段三「作者在场」,从 brief / research 里补态度、经过和对照。

约束:不新增事实;不做同义替换;不整段重写(整段重写会回到助手腔,`fidelity_check.py` 会报改写过度);`fidelity_check.py` 报缩水就是删过头了,按第 4 步往回补。

### humanize_log.md

`ai_score.py ... --log-template` 在文章同目录生成或补全骨架,已有的行不动:`density` 规则每条一行(行列写"全文 N 处",原文填 `*`);`position` 命中每条一行(行列写行号,brief 结构规划行写成 `brief L<行号>`);处理和理由两列留空。

```markdown
| 规则 | 行 | 原文 | 处理 | 理由/出处 |
|---|---|---|---|---|
| <规则 id> | <行号 / brief L行号 / 全文 N 处> | <命中片段,或 *> | 删 / 改 / 保留 | <保留时必填> |
```

- **删 / 改**:改完重跑 lint,这一条消失即可。重跑后仍被列出,说明没改到位,写了"删 / 改"也不算覆盖。
- **保留**:`处理` 列只写"保留"两个字,别的写法不算。
  - `density` 规则:一行覆盖这条规则的全部命中,原文填 `*`(或任一命中原文)。
  - `position` 命中:逐条一行,规则 id 相同,原文和命中片段对得上(去掉空白后互相包含,且至少 4 个汉字或等于整个命中片段)。一行最多覆盖一条命中,把几处原文拼进同一行不算;每条各占一个保留名额。标题、摘要、小标题、图注的命中也可以这样保留,但这些位置读者最先看到,能改就改。
  - 理由去掉空白后至少 6 个字,写清改掉会损失什么事实,有出处就写上;"无""同上""略""待补"这类占位不算。
  - `unsourced_experience`(第一人称亲历)的保留行只认 brief:理由写 `brief L<行号>` / `brief 第 n 行`,或 `brief experiences`,并且那一行 / 那一条要真实存在、和命中的句子对得上;链接、issue 证明不了是用户亲历。brief 里没有,就删掉这句。
  - `unsourced_quote`(引语)的保留行另认 URL、issue / PR 号、`@` 用户名;写 `research.md` 时 research 里要真有对应内容;写 `brief materials` / `brief L<行号>` 同样要对得上。只写「brief」、裸 `#1` 不算。
  - 这两类保留行不计入下面的上限;`publish.py` 和 `ai_score.py --check-log` 都会读同目录的 brief.md / research.md 核对。
  - 保留是例外,不是额度:保留行数有上限,超了 `publish.py` 会拒发,多出的只能改写。
- 用户本人写的稿子不走这道门,发布时用 `--skip-ai-score`。
- 冷读发现、但 A 层表里没有的新写法,在 log 末尾单列一节"新模式",供以后补进规则;3.5 里跳过的步骤也在末尾写明原因。

### 冷读审校(3.5c)

一个**全新上下文、只读**的 pass,只标不改,最多 2 轮。有 Agent 工具就开本地子代理(禁止 `isolation: "remote"`);没有,或者 Agent 会继承当前对话(例如 Codex 的 `spawn_agent`),就另起一个新会话,只给下面列出的输入;都做不到就请用户来读。跳过了就在 `humanize_log.md` 末尾写明"冷读跳过"和原因。

**第一遍(不给表)**。输入只有 `article.md` 和 voice 描述,不给本清单、brief、research。voice 描述 = SKILL.md 阶段三「写作风格」里当前账号那一段原文,加上"两个号共用"那一句;`assets/voices/<account>/samples.md` 存在时改为附上样本原文。不要粘贴 `wechat-publisher.yaml` 的 voice 字段(用户改之前它不作数),也不要粘贴账号表的「人格(voice)」列。prompt 只写任务:

```text
你是第一次读这篇稿子的编辑。作者是<作者名>,他写东西的取舍原则如下:<voice 描述>。
逐段读,标两类问题:
1. 这个人不会在群聊里这样说的句子。衔接句、有依据的态度、类比、按顺序讲的经过不算问题,不要因为一句话"可以删"就标它。
2. 读着像说明书或文档转述的段落:看不出作者觉得哪里重要、没有判断、只是把材料摊开。
只标出来,不改写,不给替换句。找不到就写"无",不要凑数。第 1 类最多 15 条,第 2 类最多 5 条。
输出格式:类别|段号|原句或段落开头|为什么
```
