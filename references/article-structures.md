# 文章结构库与开头钩子库

阶段一选定 `article_structure` 和 `opening_hook`,写进 `brief.md`。本文件只给结构类型和可选要素,不给可以照抄的开头句、过渡句或收尾句。

#### 结构选择规则

不要每篇都用"我遇到一件事"式故事开场。故事只是可选结构之一,不是默认套路。

1. 用户在指令或 frontmatter 里写了 `article_structure` / `opening_hook` → 直接使用。
2. **先读历史**:跑 `python3 scripts/fingerprint.py --account <main|tech> --last 3`(不给文章路径时只列最近几篇的特征),把最近 3 篇的结构、开头钩子、结尾类型写进新 brief 的 `recent` 字段,作为选择依据。脚本还不可用时,退一步读 `ls -t mp-articles/<account>/*/brief.md | head -3` 里的 `article_structure` / `opening_hook`。
3. 最近 3 篇出现过的"结构 + 钩子"组合不再用;开头类型、结尾类型也避开最近 3 篇的重复。
4. 题材明显时按下表匹配;不明显时从最贴近的 2-3 个候选里随机选一个。
5. `scene-first` 钩子和 `field-notes` 结构只在 brief.experiences 不为"无"时可选:写稿的人没有亲历,这两种写法只能建立在用户本人的经历上。
6. 讲"适用人群 / 不适用的情况"的收尾小节,同账号连续两篇不能都出现。
7. 同一系列(brief 里声明相同的 `series`)的文章之间不比较开头和小标题,其余照常比较。

#### 文章结构库

"可选要素"不规定顺序,也不要求全部用上;不强制用个人判断、启发或适用边界收尾。

| `article_structure` | 适合题材 | 可选要素 |
|---|---|---|
| `data-first` 数据先行 | 榜单 / benchmark / 融资 / 财报 / 模型能力 | 数字本身、谁测的、口径和可信度、和同类数据的对比、影响范围 |
| `question-led` 问题追踪 | 争议 / 真假难辨 / 产品变化 / 用户困惑 | 问题来源、正反证据、已确认的部分、尚无定论的部分、结论边界 |
| `contrarian` 反常识 | 舆论一边倒但事实更复杂 | 主流说法及出处、和它冲突的证据、证据的局限、后续影响 |
| `teardown` 拆解地图 | 新框架 / 新协议 / Agent 架构 / SDK | 整体结构、各部分职责、关键设计取舍、和旧方案的差异、适用边界 |
| `field-notes` 实测笔记 | 工具体验 / 教程 / 踩坑 / 本机实验(需 experiences) | 用户实际做了什么、怎么跑、顺的地方、卡住的地方、给读者的用法 |
| `timeline-news` 时间线 | 热点新闻 / 公司动作 / 政策 / 安全事故 | 时间点、关键角色、影响范围、接下来要盯的节点 |
| `playbook` 行动清单 | 方法论 / 技巧合集 / 入门指南 / 生产力 | 适用人群、最短路径、关键动作(按实际数量)、常见坑、不适用的情况 |
| `case-file` 案卷复盘 | 翻车 / 处罚 / 安全事件 / 商业事故 | 案件事实、证据链、问题出在哪、当事方的解释、对读者的影响 |

`contrarian` 的反差靠并列的事实来呈现;用两个带数字的事实并列开场只是可选写法之一,不是默认。任何结构都不靠先否定再翻案的句法制造反差。

#### 开头钩子库

| `opening_hook` | 写法 | 避免 |
|---|---|---|
| `hard-number` | 第一屏出现材料里的具体数字、金额、比例、版本号 | 数字单独成段;数字后面空泛感慨;编数字 |
| `sharp-question` | 用一个读者真会问的问题开场 | 紧跟自问自答 |
| `contradiction` | 把两个冲突的事实并排放出来 | 为反转而反转;用否定对照句式代替事实 |
| `quote-first` | 用当事人原话 / issue / commit message 开场,带出处 | 编造无法溯源的转述 |
| `artifact-first` | 用命令输出、日志、截图描述、排行榜条目开场 | 贴一大段无解释的技术细节 |
| `timeline-first` | 用具体日期 / 小时时间线开场 | 宏观时代背景 |
| `scene-first` | 用用户本人的经历开场(需 experiences) | 每篇都这样写;铺陈;编造场景 |

所有钩子共同的要求:开头的事实出自 brief.materials 或 experiences;不预告后文;不替读者设定一个错误认知再推翻。
